# Moneysoft Payroll Manager: automation hooks, file layout, filing logs, Windows automation

Research note for the Moneysoft → Xero hands-free payroll-journal pipeline (Digivolve). Written 2026-09-26.
Method: ~45 web searches (moneysoft.co.uk, accountingweb.co.uk, help.dropbox.com, learn.microsoft.com, docs.parallels.com, pywinauto, pdfforge, bullzip) read via result snippets only — WebFetch/curl are egress-blocked for moneysoft.co.uk and the forums, so no page was read in full. Practice-verified facts come from the existing `payroll-agent` skill (SKILL.md, `references/moneysoft-playbook.md`, `references/setup.md`, `scripts/vm_fps.sh`, `scripts/vm_export.sh`) and are labelled "practice-verified". Everything else is labelled as vendor statement, forum report, or inference.

## Summary

- **There is no API, no macro language and no documented command-line switches.** Moneysoft's own overview and every 2026 review describe a Windows-only desktop app whose only outward integration is CSV/PDF/email. The one thing the executable (`pm3.exe`) demonstrably accepts is a `.pay` path as its argument (file association) — the practice already relies on this. Everything else must be driven through the UI.
- **The FPS submission log lives inside the `.pay` file, not in a separate log file.** Moneysoft says each data file has its own Submission Log and that restoring an older copy of the file loses the record of a submission. Therefore a successful filing necessarily rewrites the `.pay` (and, we infer, rotates the `.bk1..bk5` auto-backups). A file-system watcher on the `.pay` mtime is a viable "something happened" trigger, but it cannot by itself distinguish "FPS filed" from "pay entered" — the authoritative filed/unfiled state is the Employer's RTI schedule (practice-verified: rows show `View` = filed vs `View / File` = unfiled) and the Submission Log (Tools → Online Filing → Submission Log). No HMRC-response file, receipt file or per-employer log file exists on disk that we could find.
- **Two Moneysoft features could remove whole stages of UI driving and were not in the current design:** (a) a **Pay → "Accounting file"** CSV export intended for import into bookkeeping software (forum-reported; layout undocumented on the web), which could replace PDF parsing as the journal source; and (b) the **RTI batch processor** (multi-company licences only) which files FPS/EPS for many employers "without the need to first open and close each data file". Both must be checked on the office machine before the architecture is fixed.
- **Dropbox as the live data store is explicitly against vendor advice.** Moneysoft does not support networked/shared use; a user reported being told by Moneysoft support "do not use Dropbox to store main files, only backups"; AccountingWEB threads describe conflicted copies and corrupt files when two machines touch the same file. Moneysoft has an in-app lock ("something outside of Payroll Manager is blocking access to this file") that refuses a second open, but Dropbox's own conflict rules ("a file is left open on another user's computer") still apply. The pipeline needs a single-writer rule, a stale-copy detector and a conflicted-copy scanner as first-class components.
- **Windows-side automation is feasible but only in an interactive, unlocked, logged-on session.** `prlctl exec` (Pro/Business edition only) runs in session 0 unless `--current-user` is used; the practice's working pattern is an interactive scheduled task (`schtasks /IT /RU <user>`) running PowerShell that uses window enumeration + `PostMessage` (never `SendMessage`, which deadlocks on modal dialogs) + SendKeys. pywinauto's `win32` backend covers VCL/VB6/MFC apps but Delphi menus are reported as hard to address; UIA via PowerShell is an option. Silent PDF output needs either a fixed-path local port on Microsoft Print to PDF (then rename), or PDFCreator/Bullzip in auto-save mode; Moneysoft's printer is chosen at Tools → Setup → Reports & Printing.
- **The `.pay` format is proprietary and undocumented.** Every migration tool (paiyroll, Staffology, BrightPay) imports from Moneysoft via its FPS XML / CSV exports, never by reading `.pay`. Do not build anything that parses `.pay`; the `.pfi` sidecar (practice-verified: field 12 = current pay-period end) is the only cheap read-only signal.
- **Operational facts that shape scheduling:** one `.pay` per employer per tax year (names change every April); in-year program updates roughly every two months with an in-app prompt that can appear mid-session and needs admin rights to install; Windows 11 is mandatory since May 2026; licence permits the same code on two machines only if not run simultaneously (concurrent users need extra licences); support is phone for program faults and email (one working day) for filing IDs/data files/licences.

## Findings

### 1. No API, no scripting facility, no integration beyond CSV/PDF/email
**Confidence: high.**
Moneysoft's product pages list the outputs as payslips, reports, BACS files, pension files, "CSV files for other accounting systems" and automatic posting to its own Money Manager. Independent 2026 reviews state there is "no browser workspace, native employee app, broad API" and that it "lacks ... automated API integrations with modern accounting platforms like Xero"; journals for Xero are "a manual process". Nothing on moneysoft.co.uk mentions a macro, script or automation facility, and no third party advertises one. The practice's own playbook opens with "Moneysoft has no API. You drive it the way a person does."
Sources: [Payroll Manager overview](https://moneysoft.co.uk/payroll-manager-overview/), [hr.software review 2026](https://www.hr.software/reviews/moneysoft-payroll-manager), [expertsure review 2026](https://www.expertsure.com/uk/payroll/moneysoft-review/), [AccountingWEB Moneysoft review](https://www.accountingweb.co.uk/reviews/payroll/moneysoft).

### 2. Command line: the executable is `pm3.exe`; a `.pay` path as argument works; no other switches are documented
**Confidence: medium** (argument behaviour practice-observed; absence of switches is an absence of evidence).
PC Matic's file-extension library lists `pm3.exe` as the Payroll Manager application that opens `.pay` files (older networking threads reference `WINPAY.EXE`). No page on moneysoft.co.uk documents any command-line switch (silent, print, export, open). Practice-verified: `open -a "Parallels Desktop" "<file>.pay"` from the Mac opens that employer in the running instance ("switches files in the same window") — i.e. the file association passes the path through and a second invocation hands the file to the existing instance rather than spawning another. The playbook also records that launching a second copy against an already-open file produces "something outside of Payroll Manager is blocking access", confirmed by AccountingWEB where Moneysoft explained the message means "the program is running twice".
Sources: [PC Matic pm3.exe](https://www.pcmatic.com/company/libraries/fileextension/application.asp?appname=pm3.exe.html), [PC Matic .pay](https://www.pcmatic.com/company/libraries/fileextension/detail.asp?ext=pay.html), [AccountingWEB "Problems opening Moneysoft Payroll Manager"](https://www.accountingweb.co.uk/any-answers/problems-opening-moneysoft-payroll-manager), [AccountingWEB "can it be networked"](https://www.accountingweb.co.uk/any-answers/moneysoft-can-it-be-networked).

### 3. File layout: `.pay`, `.bk1`–`.bk5`, `.pbu`, `.pfi`
**Confidence: medium** (forum-derived; vendor pages confirm only `.pay`, the default folder and the backup menu).
- `.pay` — the live employer file; **one per employer per tax year** (Moneysoft: "each company that you process payroll for has a separate payroll data file for each tax year"; practice naming `<Employer> <YYYY-YY>.pay`). Default folder `C:\Users\<user>\Documents\Payroll`.
- `.bk1`…`.bk5` — AccountingWEB users describe these as "sequential back-up versions in date order from the last processing/changes (.bk1 being the most recent and .bk5 the oldest)", i.e. Moneysoft keeps a rolling five-deep automatic backup beside the `.pay`. The vendor's "How to proceed after restoring or reverting to a previous copy" page confirms reverting to earlier copies is a supported operation.
- `.pbu` — created by the manual `File → Utilities → Backup/Restore → Save Backup` / `Backup all Files in default folder`. There is a separate "Anonymous backup" for sending to support.
- `.pfi` — described on AccountingWEB as "related to auto-enrolment and seem to contain the same info as the file selection menu". Practice-verified: it is a delimited sidecar whose field 12 is the current pay-period end, readable in milliseconds without opening Moneysoft (`pfi_scan.py`).
No automatic *scheduled* backup facility exists; AccountingWEB advice is that "everything is contained in one file" so ordinary Windows backup/robocopy on a scheduled task suffices.
Sources: [Moneysoft "Data File Questions"](https://moneysoft.co.uk/support/data-file-questions/), [Moneysoft "Copying a data file"](https://moneysoft.co.uk/support/copying-payroll-manager-data-file-one-computer-another/), [Moneysoft "Moving to a new computer"](https://moneysoft.co.uk/support/moving-payroll-manager-to-new-computer/), [AccountingWEB "Moneysoft payroll" (.bk/.pfi/.pbu)](https://www.accountingweb.co.uk/any-answers/moneysoft-payroll-12), [AccountingWEB "automatic backup?"](https://www.accountingweb.co.uk/any-answers/moneysoft-payroll-manager-automatic-backup), [Moneysoft GDPR page (anonymous backup)](https://moneysoft.co.uk/support/gdpr-and-payroll-manager/).

### 4. The RTI Submission Log is stored inside each `.pay` file
**Confidence: high** (vendor statements).
"Each Payroll Manager data file has its own Submission Log, containing details of RTI returns submitted for that employer in that particular tax year." And: "If you have gone back to a copy of the data file that was saved before an RTI submission was made then the software will not have a record of that particular return having been sent" — after which the RTI schedule simply drops the earlier period. Access: **Tools → Online Filing → Submission Log**, three tabs; select a submission → **Details** shows date/time sent/received and the **IR Mark**; for successful submissions there are **Sent data** and **HMRC response** buttons; the log is printable ("the ability to print confirmation of successful transmission"). No page describes exporting the log to a file — printing (to a PDF printer) is the only documented way out.
Sources: [Moneysoft "Submission Log"](https://moneysoft.co.uk/support/submission-log/), [Moneysoft "How to proceed after restoring"](https://moneysoft.co.uk/support/how-to-proceed-after-restoring-or-reverting-to-a-previous-copy-of-a-payroll-data-file/), [Moneysoft RTI user information](http://www.moneysoft.co.uk/payroll-software/payroll-manager-rti-user-info.htm), [Moneysoft "Online Filing Questions"](https://moneysoft.co.uk/support/online-filing-questions/).

### 5. File-system trace of a successful FPS: the `.pay` is rewritten; nothing else appears on disk
**Confidence: medium** (inference from finding 4 plus practice observation; not directly stated by the vendor).
Because the log is inside the data file, a successful filing must persist into the `.pay` (modified time changes) and, given the `.bk` rotation, probably shifts `.bk1..bk5`. No HMRC-responses folder, receipt file or correlation-ID file is documented anywhere. The HMRC acknowledgement itself carries a CorrelationID, GatewayTimestamp and the IRmark — all of which Moneysoft shows only in the Submission Log UI. Practice-verified detection method today: re-open **Pay → Employer's RTI schedule** and count filed rows (`filed_after == filed_before + 1` is treated as definitive; HMRC's success popup is transient and was missed on four consecutive accepted filings). Rows read "filed online on <date>".
Sources: [Moneysoft "Submission Log"](https://moneysoft.co.uk/support/submission-log/), [Moneysoft "Sending your first RTI submission"](https://moneysoft.co.uk/support/sending-rti-hmrc/), [Moneysoft "Running the payroll – standard procedures"](https://moneysoft.co.uk/support/running-payroll-standard-procedures/), [craigfrancis/hmrc-rti gateway response fields](https://github.com/craigfrancis/hmrc-rti/blob/main/hmrc-gateway.php).

### 6. Outstanding/uncertain submissions: never resubmit inside 24 hours
**Confidence: high.**
Moneysoft's guidance on "Outstanding RTI Submissions" (May 2025) is to wait at least 24 hours before resubmitting because a duplicate accepted return makes HMRC "double up" the figures. The Employer's RTI schedule can also be used to resubmit deliberately ("Payroll corrections and RTI returns").
Sources: [Moneysoft "Outstanding RTI Submissions"](https://moneysoft.co.uk/support/outstanding-rti-submissions/), [Moneysoft "Payroll corrections and RTI returns"](https://moneysoft.co.uk/support/payroll-corrections-and-rti-returns/).

### 7. RTI batch processor (PM100/PM250) files many employers' FPS/EPS without opening each file
**Confidence: medium** (vendor page exists and is described in snippets; exact menu path and its log unverified).
"All multi-company versions of Payroll Manager include the 'RTI batch processor'". Workflow from the vendor page and AccountingWEB: **Add files** (employers) to the batch → **Select all** (or a subset) → **File returns for selected files**; "each month Payroll Manager would file FPS and EPS returns as necessary without the need to first open and close each data file". Users report it once "failed to identify returns that are due" (a return showed as late after a batch run), so its due-detection is not to be trusted blindly. Results of each filing still land in each file's own Submission Log.
Sources: [Moneysoft "The RTI Batch Processor"](https://moneysoft.co.uk/support/rti-batch-processor/), [Moneysoft RTI FAQs](https://moneysoft.co.uk/real-time-information-rti-faqs/), [Moneysoft agents & accountants](https://moneysoft.co.uk/agents-accountants/), [AccountingWEB "RTI batch processor failing to identify returns that are due"](https://www.accountingweb.co.uk/any-answers/moneysoft-payroll-manager-rti-batch-processor-failing-to-identify-returns-that-are-due), [AccountingWEB "Moneysoft RTI batch processor"](https://www.accountingweb.co.uk/any-answers/moneysoft-rti-batch-processor).

### 8. A built-in "Accounting file" CSV export exists under the Pay menu
**Confidence: medium** (forum report consistent with vendor marketing; layout and nominal-code setup undocumented on the web).
AccountingWEB: "Moneysoft does have an Accounting File option under Pay which will extract a .CSV file for import into your book-keeping software" (mentioned in the context of posting gross pay by department). Vendor: "automatic posting of data to Money Manager and CSV files for other accounting systems". One forum comment claims it "posts the journal directly over to Xero" — this contradicts every vendor page and review and should be treated as wrong until seen on screen. Also documented: **Tools → Export Data → Export Employee data to a CSV file** ("Everything") and **Pay Details import from CSV** (hours per employee), which matter for the input side.
Sources: [AccountingWEB "Payroll software"](https://www.accountingweb.co.uk/any-answers/payroll-software-60), [Payroll Manager overview](https://moneysoft.co.uk/payroll-manager-overview/), [Staffology "Import from Moneysoft"](https://help.staffology.co.uk/payroll/administration/import-export/import-moneysoft.htm), [Moneysoft "Importing data into the Pay Details screen"](https://moneysoft.co.uk/support/importing-data-pay-details-screen/), [MyICB forum "Extracting a Monthly Journal"](https://www.bookkeepers.org.uk/forum/?tid=89089).

### 9. Reports to PDF: toolbar "Save as pdf" auto-names; "Print All Reports → Save all open reports as a PDF file" is keyboard-reachable
**Confidence: high for the vendor part; practice-verified for the menu chain.**
Vendor: any report can be saved as PDF via the toolbar "Save as pdf" button; PDF password protection is a per-file setting; a Tools → Setup option adds the employee ID to payslip file names; the printer for reports is chosen at **Tools → Setup → Reports & Printing**, and Windows' "Let Windows manage my default printer" must be off or Moneysoft reports "no default printer"/"printer selected is not valid". Practice-verified: the toolbar button is mouse-only and synthetic clicks do not reach the Parallels guest, so the working path is **File → Print All Reports → Save all open reports as a PDF file** (one Down below "Print all open reports to the printer"), whose Save dialog defaults to `C:\Mac\Home\Documents`; open only the three needed previews first (Employer's Summary Basic layout, payslips, P30) because *every* open report window is swept into the combined PDF. Nothing on the web describes a settable default PDF output folder.
Sources: [Moneysoft "Emailing payslips and reports"](https://moneysoft.co.uk/support/emailing-payslips-and-reports/), [Moneysoft "Handy tips"](https://moneysoft.co.uk/support/handy-payroll-manager-tips/), [Moneysoft "Printers & Printing Problems"](https://moneysoft.co.uk/support/printers-printing-problems/), [Moneysoft "Windows default printer"](https://moneysoft.co.uk/support/windows-default-printer/), [MyDocSafe Moneysoft guide (employee-ID filename option)](https://help.mydocsafe.com/en/articles/4172224-moneysoft-and-payslips).

### 10. Dropbox/OneDrive/network storage is unsupported by the vendor and a documented source of conflicts and corruption
**Confidence: high** for the vendor position and Dropbox mechanics; **medium** for the "support said don't" quote (single forum report).
- Vendor: Payroll Manager is "NOT designed" for networked use; the only supported multi-machine patterns are backup/restore between machines and "temporarily using Payroll Manager on a different computer". A forum poster relayed Moneysoft support's advice: "do not use Dropbox to store main files, only backups". Another: "OneDrive can generate conflicted copies of files if 2 people open Moneysoft at the same time which ... can be a nightmare to sort out"; "files for large clients corrupt if not used on the server".
- Moneysoft's own guard: it "will prevent you from opening the payroll file" if another PC has it open (the "something outside of Payroll Manager is blocking access" message) — this is an in-process/OS file lock, which only helps when both machines see the same lock, i.e. never across two Dropbox replicas.
- Dropbox: a conflicted copy is created when "two users change the same file at the same time", when someone edits offline, or when "a file is left open on another user's computer"; Dropbox reports "file in use" when an app holds an exclusive lock; Dropbox offers explicit **file locking** (team feature) that blocks edits by others. On macOS Dropbox now runs on Apple's File Provider, where files can be online-only placeholders — a `\\Mac\...` shared-folder read from Windows of an online-only file is a failure mode to rule out.
- Practice-verified: SharePoint was abandoned for the pay files because it "synced unreliably"; three stale copies of the Moneysoft folder existed on one Mac (Dropbox 263 files live; SharePoint 34 files; Google Drive 4 files).
Sources: [Moneysoft "Working from home"](https://moneysoft.co.uk/support/working-from-home-payroll-manager/), [Moneysoft "Temporarily using on a different computer"](https://moneysoft.co.uk/support/temporarily-using-payroll-manager-on-a-different-computer/), [AccountingWEB "Online File Storage"](https://www.accountingweb.co.uk/any-answers/online-file-storage-1), [AccountingWEB "missing payroll info on diff. computers"](https://www.accountingweb.co.uk/any-answers/moneysoft-missing-payroll-info-on-diff-computers), [AccountingWEB "Corrupted File"](https://www.accountingweb.co.uk/any-answers/corrupted-file), [AccountingWEB "on a server?"](https://www.accountingweb.co.uk/any-answers/moneysoft-payroll-manager-on-a-server), [Dropbox "What's a conflicted copy?"](https://help.dropbox.com/organize/conflicted-copy), [Dropbox file locking](https://help.dropbox.com/organize/file-locking), [Dropbox online-only files on macOS](https://help.dropbox.com/sync/online-only-mac), [Dropbox on File Provider](https://help.dropbox.com/installs/macos-support-for-expected-changes).

### 12. Version cadence, update mechanism and OS requirements
**Confidence: high.**
Updates ship "at various intervals throughout the year (approximately every 2 months)"; users "will be automatically prompted to update ... whilst using the software if a scheduled update is due"; manual check at **Help → Program Update**; installing needs an administrator account (Program Files write). Parallels on Apple silicon runs Windows 11 ARM, where x86 apps run through Microsoft's Prism translation; the practice already runs Moneysoft this way, so it works in fact even though it is unsupported.

### 14. `.pay` is a proprietary, undocumented binary format
**Confidence: medium** (no vendor statement either way; strong indirect evidence).
No documentation of the `.pay` structure exists on moneysoft.co.uk or anywhere found. Every vendor that migrates *from* Moneysoft — paiyroll, Staffology, BrightPay — does so from Moneysoft's **FPS XML file** and **employee CSV export**, not from `.pay`, which is what one expects when the native format is closed. Whether the file is encrypted is unknown; Moneysoft's GDPR page discusses PDF passwords and anonymous backups but says nothing about data-file encryption. Reading `.pay` directly is neither documented nor supported and is not recommended. The `.pfi` sidecar, by contrast, is plain delimited text (practice-verified).
Sources: [paiyroll "Migrate from Moneysoft"](https://login.paiyroll.com/static/sphinx/html/user/guides/GB/import_moneysoft.html), [BrightPay "Importing from Moneysoft using an FPS file"](https://www.brightpay.co.uk/docs/23-24/moving-to-brightpay-from-another-payroll-software/importing-from-moneysoft/importing-from-moneysoft-using-an-fps-file/), [Staffology "Import from Moneysoft"](https://app.staffology.co.uk/userguides/importexport/import-moneysoft), [Moneysoft GDPR and Payroll Manager](https://moneysoft.co.uk/support/gdpr-and-payroll-manager/).

### 15. Running automation inside the Parallels guest: session, edition and focus constraints
**Confidence: high** (vendor docs + practice-verified).
- `prlctl` is only in Parallels Desktop **Pro/Business** editions. `prlctl exec <vm> <cmd>` needs Parallels Tools; docs say `--current-user` "log[s] in as the user currently logged in inside the guest OS" (or `--user`). Practice-verified: plain `prlctl exec` "is SYSTEM in session 0 and can neither see windows nor send keys", so the working pattern is `prlctl exec ... schtasks /run /tn <task>` where the task was registered `/IT /RU <guest_user>` (interactive, that user must be logged on) — Microsoft: "/it ... run the scheduled task only when the run as user ... is logged on"; "Run only when user is logged on" is the mode that "permits on-screen windows". Whether `prlctl exec --current-user` alone reaches the interactive desktop has **not** been tested by the practice (a forum thread notes it pops a cmd box, which implies it does run in the user session).
- SendKeys "blast[s] keystrokes out to whatever window currently has the focus"; SetForegroundWindow fails when the session is locked or a screensaver is active; a locked/blanked guest also makes `prlctl capture` return black/0-byte images (practice-verified). Auto-logon + no lock + no screensaver + `caffeinate` on the Mac are prerequisites.
- Practice-verified pitfalls: use `PostMessage`, never `SendMessage`, to click buttons that open modal dialogs (SendMessage blocks forever); wait for window state rather than sleeping; some controls (the submission Result box) are unreadable via `GetWindowText`; window titles are invisible from session 0 so enumerate from the interactive task.
Sources: [Parallels "Execute a Command in a Virtual Machine"](https://docs.parallels.com/parallels-desktop-developers-guide/command-line-interface-utility/manage-virtual-machines-from-cli/general-virtual-machine-management/execute-a-command-in-a-virtual-machine), [Parallels forum "prlctl is now Pro/Business only"](https://forum.parallels.com/threads/prlctl-is-now-a-pro-or-business-version-tool-only.330290/), [Parallels forum "prlctl exec --current-user without cmd box"](https://forum.parallels.com/threads/prlctl-exec-current-user-without-cmd-box.349374/), [Microsoft schtasks](https://learn.microsoft.com/en-us/windows/win32/taskschd/schtasks), [ss64 schtasks](https://ss64.com/nt/schtasks.html), [Microsoft Q&A on GUI tasks and logon type](https://learn.microsoft.com/en-us/answers/questions/2188387/task-scheduler-does-not-work-with-the-option-run-w), [TechRepublic on SendKeys](https://www.techrepublic.com/article/automate-tasks-with-windows-script-hosts-sendkeys-method/).

### 16. UI-automation libraries for a legacy keyboard-driven Win32 app
**Confidence: medium.**
pywinauto's default `win32` backend "supports MFC, VB6, VCL, simple WinForms controls and most old legacy apps"; the `uia` backend is slower and aimed at WinForms/WPF/Qt. A pywinauto discussion thread is titled "Delphi Apps hard to control" and a GitHub issue notes `menu_select()` works better under `uia` for some menu bars — so expect menus to need accelerator keystrokes (F10/Alt + letter, which the practice already uses) rather than semantic menu selection. PowerShell can drive `System.Windows.Automation` (UIA) directly, and Win32 menu items expose the Invoke pattern. AutoHotkey `ControlSend` avoids needing foreground focus but "is not completely reliable ... with certain windows". Keyboard accelerators + window/button enumeration by handle (the practice's `pa_click`, `pa_enum`) remain the most robust primitive.

### 17. Silent PDF output without a Save dialog
**Confidence: high.**
- **Microsoft Print to PDF** uses the `PORTPROMPT:` port, which always shows "Save Print Output As". Documented workaround: `Add-PrinterPort -Name "C:\out\fixed.pdf"` then `Add-Printer -Name "PDF Fixed" -DriverName "Microsoft Print to PDF" -PortName "C:\out\fixed.pdf"` — output goes to that fixed path with no dialog; the caller must then move/rename it (and note the fixed file is overwritten each print). Setting `PrinterSettings.PrintToFile/PrintFileName` from code is reported unreliable with this driver.
- **PDFCreator** "Automatic" save mode "will skip all user interaction" once a target folder and filename template (tokens such as `<DateTime>`) are set on a profile bound to a printer.
- **Bullzip** `global.ini`: `Output=C:\Archive\<...>.pdf`, `ShowSettings=never`, `ShowSaveAS=never`, `ShowProgress=no`, `ShowPDF=no`, `ConfirmOverwrite=no`.
- Moneysoft picks its printer at Tools → Setup → Reports & Printing, so a dedicated auto-save printer can be made the Moneysoft report printer without touching the Windows default.
Sources: [MS Q&A "Microsoft Print to PDF" PORTPROMPT](https://learn.microsoft.com/en-us/answers/questions/3298468/microsoft-print-to-pdf), [MrExcel local-port recipe](https://www.mrexcel.com/board/threads/setting-up-a-local-printer.1248227/), [MSDN forum on programmatic filename](https://learn.microsoft.com/en-us/archive/msdn-technet-forums/e9eb9fdf-c1f2-403a-abc9-678535e9606f), [Add-PrinterPort](https://learn.microsoft.com/en-us/powershell/module/printmanagement/add-printerport), [PDFCreator Autosave Mode](https://docs.pdfforge.org/pdfcreator/en/pdfcreator/using-pdfcreator/autosave-mode/), [PDFCreator Save settings](https://docs.pdfforge.org/pdfcreator/en/pdfcreator/pdfcreator-settings/profile-settings/save/), [Bullzip global settings](https://www.bullzip.com/kb/global-settings/), [Moneysoft "Windows 10 default printer"](https://moneysoft.co.uk/support/windows-10-default-printer/).

### 18. Built-in payslip/report emailing with per-file PDF passwords and agent-wide settings
**Confidence: high.**
Payroll Manager can create emails with PDF attachments (payslips/reports), password-protect each PDF (recommended for GDPR), send one email per employer containing one PDF per employee protected by each employee's password, and "if you are a payroll agent ... apply these settings across all of your payroll files". Sending goes through the user's SMTP/Outlook/Gmail/Office 365 configuration. Relevant only if the pipeline ever wants Moneysoft itself to distribute payslips rather than the Mac-side splitter.

## Implications for the pipeline design

1. **Trigger design.** Use a two-stage detector: (a) cheap file-system signal — `.pay` mtime changed (or `.bk1` rotated) in the Dropbox folder, read from the Mac side without touching Moneysoft; (b) authoritative confirmation — open the employer in the guest and read the Employer's RTI schedule (filed-row count / "filed online on") or the Submission Log. Never treat the mtime alone as "FPS filed": pay entry, DPS notices and even opening/closing can rewrite the file. Never build a watcher that expects a receipt file — none exists.
2. **Journal source.** Verify on the office machine whether **Pay → Accounting file** produces a CSV with per-employee gross / ER NIC / PAYE / net (and EA). If it does, it should replace `split_reports.py` + PDF parsing as the figures source (structured, no OCR-style column inference), with the Employer's Summary PDF kept only as the human-readable attachment and cross-check. If the CSV lacks the employment allowance or pension split, keep the PDF parser as the reconciliation source.
3. **Filing stage.** Evaluate the **RTI batch processor** as the filing engine for the simple director/salaried clients: one batch per run day instead of ~N × (open file → schedule → wizard → check responses). Keep the per-file schedule check as the post-condition regardless, because the batch processor has a documented history of mis-detecting due returns, and each file's Submission Log is still where the proof lives.
4. **Data-store hygiene is a component, not an assumption.** Single-writer rule (only one Mac/VM runs Moneysoft against the Dropbox folder at a time; enforce with a lock file or Dropbox file locking), a pre-run scan for `* (conflicted copy)*.pay`, `.bk*` newer than `.pay`, duplicate employer names, and online-only placeholders; refuse to run a client whose file fails the scan. Keep periodic robocopy/`.pbu` snapshots to a non-synced location because the vendor's `.bk1..bk5` rotate inside the same synced folder.
5. **Guest automation contract.** Stay with the proven pattern: interactive scheduled task (`/IT /RU`), PowerShell + window enumeration + `PostMessage` + keystrokes, state-waits not sleeps, guest never locked/blanked, Mac `caffeinate`d. Test `prlctl exec --current-user` once — if it reaches the interactive desktop it removes the `guest_user`/schtasks indirection and one failure point. Parallels must stay on Pro/Business for `prlctl`.
6. **PDF output.** Replace the typed-`x`-into-Save-dialog step with a dedicated auto-save printer (Microsoft Print to PDF on a fixed-path local port, or PDFCreator/Bullzip autosave) selected in Tools → Setup → Reports & Printing, so the "Print all open reports to the printer" item becomes safe and no dialog is ever raced. Move/rename the fixed output immediately after each client.
7. **Do not parse `.pay`.** Use `.pfi` for period detection, Moneysoft's own exports (Accounting file CSV, employee CSV, FPS XML) for data, and the UI for state.
8. **Calendar and maintenance guards.** Detect and dismiss/defer the in-app "Program Update" prompt (it will appear mid-batch roughly every two months and needs admin to install; schedule updates deliberately outside run windows). Handle the April rollover: new `<Employer> 2027-28.pay` files appear, registry `moneysoft_file` names change, and the first run of the year must confirm the file was created. Windows 11 guest only.
9. **Licensing.** Two staff Macs each running Moneysoft against the same folder at the same time is both a licence breach and a corruption risk; the pipeline should run on one designated machine (or two licences plus the single-writer lock).
10. **Failure handling stays conservative.** Timeout or unclear FPS outcome → HOLD, re-read the schedule, never resubmit within 24 hours.
